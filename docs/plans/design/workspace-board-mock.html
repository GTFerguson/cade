Workspace board: what it could feel like

Three ways to put tickets, handoffs, worktrees and pull requests in one place, plus what cleaning up looks like. All data here is invented. Nothing below is built; the tab bar, chips and pull request badges are as they are today.

A  A board per workspace

A full-pane screen like the picker, opened with one key from anywhere in the workspace. One row per stream of work. Everything in a row is fetched, not typed: the ticket from Linear, the handoff and worktree from disk, the pull request from GitHub, the session from CADE.

  • Enter on a row opens a tab in that worktree with the agent reading the handoff, or switches to the tab if one is already open. The row with a session shows the same status mark its tab does.
  • No ticket and no handoff show as gaps, which is what the hand-kept board is mostly for finding.
  • Finished is the cleanup backlog, with its size. It is a verdict CADE works out; removing anything is the skill's job (D).
  • Costs a key and a screen. Nothing changes in the tab bar.

B  Inside the picker

No new screen. The picker you already open for a new tab gains a second view of its left column: streams of work, as well as folders. The right column becomes the detail of whatever is selected, and Enter still means "open a tab".

  • One screen answers both "what am I working on" and "open a tab on it", and the keys are the ones the picker already has.

C  No board: it lives where you already look

Nothing to open. The active tab gets a one-line strip saying what it is working on, and the list you already get by holding Alt after Alt+w carries each workspace's counts.

  • Zero new keys and zero new screens. The strip is always about the tab in front of you, so there is nothing to keep in sync by hand.
  • It only shows work that has a tab open. Streams with no session (a backlog ticket, a parked handoff, the 18 finished worktrees) have nowhere to appear except as a count.
  • Costs one row of terminal height on every tab.

D  Cleaning up, whichever of those leads to it

CADE never removes anything. "Clean up" opens a tab where an agent runs the cleanup skill on the finished list, shows what it will do, and waits.

  • The skill only uses the git commands that refuse when work would be lost, and it says what it left and why.
  • Remote branches and edits to handoffs are left alone in this version.

How they combine

These are not exclusive. C is cheap and always on; A or B is where you go for the streams that have no tab. The real choice is between A and B: a board of its own, or the picker doing double duty.
